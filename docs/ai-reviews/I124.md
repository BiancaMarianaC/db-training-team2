## Fix shipped — finding #2 (`enable.idempotence=true`)

Idempotent producers prevent duplicate records when a network blip causes
the broker ack to time out and the client retries: the broker dedupes by
producer-id + sequence-number per partition. Combined with `acks=all`
this is the standard production posture — without it, a flaky connection
during the Day-10 demo could show up as duplicate audit-log rows.

```yaml
# application.yml
spring:
  kafka:
    producer:
      acks: all
      properties:
        enable.idempotence: true   # TICKET-I124
```
